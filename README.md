# レコード管理アプリ

大磯アーカイヴ向けの無料MVPです。iPhoneで写真3枚と最小情報を入力し、AI仮価格・市場データ価格・人の確定価格を分けたマスターへ下書き化して、確認後にCSV/JSONで出力できます。

## 起動

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:4173/` を開きます。

## 現在の範囲

- 写真3枚の入力
- 価格3層を分離したマスター形式の下書き作成
- OpenAI画像解析による一次判定下書き作成
- Discogs APIによるリリース候補検索
- 要確認フラグ
- 山田確認後のマスター承認
- CSV/JSON出力
- POPUP、専門店、保留候補の簡易抽出
- Googleスプレッドシート同期

画像はブラウザのIndexedDB、レコード本文はlocalStorageへ保存します。無料MVPとしてのローカル保存なので、本番運用ではSupabaseやGoogle Drive連携へ移す想定です。

## OpenAI一次判定

写真と補足情報を入れて `AI一次判定して下書き作成` を押すと、盤の候補、価格帯、販売区分、確信度、要確認理由を作り、価格3層を分けたマスターへ変換します。手入力済みのArtist・Title・型番・国はAIで上書きせず、違いがあれば要確認にします。

Discogs APIはリリース候補の照合だけに使い、Medianや販売履歴は自動取得しません。候補を人が採用するとRelease ID・URL・照合日時を保存します。Medianはリンク先で人が確認して入力します。DU、Face、BBQは査定金額ではなく、取扱文脈との相性を参考表示します。盤を一意に特定できない場合、価格は空欄のまま `要照合` になります。

### 価格3層

- `AI仮価格`: OpenAI一次判定の下限・上限・価格帯・確信度です。画面では読み取り専用です。
- `市場データ価格`: 人が確認したDiscogs Median、国内換算価格、取得元、取得日時です。Medianを入力すると取得元を `Discogs（人が確認）` とし、取得日時を自動記録します。
- `人が確定した販売価格`: 人の確定価格、確定者、確定日時です。確定価格を入力すると確定日時を自動記録し、確定者が空欄なら要確認にします。
- `実売価格`: 販売後の価格と実売日を残します。

承認済みレコードもマスターの `編集` から下書きへ戻せます。編集したレコードは未同期へ戻り、承認後にSheetsへ更新送信できます。旧版の `ユーザー向け販売価格` は最終価格へ自動転用せず、`移行前販売価格` として保全します。

APIキーはブラウザへ保存せず、Vercel FunctionsからOpenAIへ送信します。

### Vercel環境変数

1. Vercelの対象プロジェクトで `Settings` -> `Environment Variables` を開きます。
2. `OPENAI_API_KEY` にOpenAI APIキーを設定します。
3. `APP_ACCESS_TOKEN` にスタッフだけが知る任意のアクセスコードを設定します。
4. `DISCOGS_TOKEN` にDiscogsのPersonal Access Tokenを設定します。
5. `SHEETS_WEB_APP_URL` にApps Scriptの `/exec` URLを設定します。
6. `SHEETS_SYNC_SECRET` に32文字以上のランダムな同期署名鍵を設定します。
7. 必要な場合だけ `OPENAI_MODEL` を設定します。未設定時は `gpt-4.1-mini` です。
8. Productionを再デプロイします。

AI判定またはSheets同期を最初に押した時だけアクセスコードを入力します。コードはそのタブ内だけに保持されます。

以前の版でブラウザ保存したAPIキーは、新しいキーへローテーションしてください。ローカルの簡易HTTPサーバーでは画面確認だけでき、AI判定はVercel公開URLで実行します。

## Discogs照合

下書き確認の `Discogs照合` で `候補を検索` を押すと、型番・アーティスト・タイトルから最大8件のリリース候補を表示します。候補を採用した後に `ページを開く` からReleaseページを確認し、Medianを市場価格欄へ入力します。APIトークンはVercelだけに保存し、ブラウザやスプレッドシートへは出しません。

Discogs APIから取得するのはカタログ照合用メタデータだけです。Marketplace価格・価格提案・販売履歴は自動取得、保存しません。公開画面でAPI由来データを表示する場合は、Discogsの最新API利用規約と帰属表示要件も確認してください。

## Googleスプレッドシート同期

Apps Script側にHTMLファイルは不要です。`Code.gs` だけを使い、WebアプリURLはデータ受信用のAPIとして扱います。

1. Googleスプレッドシートを作成します。
2. `拡張機能` -> `Apps Script` を開きます。
3. `google-apps-script/Code.gs` の内容を貼り付けます。
4. Apps Scriptの `プロジェクトの設定` -> `スクリプト プロパティ` に `SHEETS_SYNC_SECRET` を追加し、Vercelと同じ署名鍵を設定します。
5. `script.google.com` から独立したApps Scriptプロジェクトを作った場合は、同じ画面で `SPREADSHEET_ID` にスプレッドシートURLの `/d/` と `/edit` の間のIDを設定します。シート内からApps Scriptを開いた場合、この設定は不要です。
6. 関数 `setupMasterSheet` を一度実行して権限を承認し、`48枚マスター` シートが作成されることを確認します。
7. `デプロイ` -> `新しいデプロイ` -> 種類 `ウェブアプリ` を選びます。
8. 実行ユーザーは自分、アクセス権は `全員` または `リンクを知っている全員` にします。
9. 発行された `/exec` で終わるURLをVercelの `SHEETS_WEB_APP_URL` に設定します。
10. `Sheets同期` を押すと、承認済みで未同期のレコードが40件ずつ `48枚マスター` シートへ追記/更新されます。OpenAI解析済みのレコードは、追加列に `次回確認項目` と `AI解析JSON` も保存されます。

価格3層またはDiscogs照合へ更新した場合は、最新の `Code.gs` を貼り付けてWebアプリを新バージョンとして再デプロイしてください。既存ヘッダーは保持され、不足している列が右端へ追加されます。

Vercel Functionsが同期データへHMAC署名し、Apps Scriptが署名・有効時刻・再送を検証します。URLを知っているだけでは書き込めません。Apps Scriptが返したUIDまで照合し、受理されたレコードだけを同期済みにします。

## 新しいスプレッドシートへ移行

1. 新しいGoogleスプレッドシートを作成します。
2. 新しいシート側で `拡張機能` -> `Apps Script` を開きます。
3. `google-apps-script/Code.gs` を丸ごと貼り付けます。
4. Webアプリとして新しくデプロイし、`/exec` URLを取得します。
5. Vercelの環境変数 `SHEETS_WEB_APP_URL` に新しい `/exec` URLを設定します。
6. Vercelを再デプロイします。
7. 既存データも新しいシートへ送りたい場合は、`同期状態リセット` を押します。
8. `未同期を送信` を押します。

## 同期テスト

`運用` タブの `テストデータ作成` を押すと、承認済み・未同期のサンプルレコードを1件作成します。そのまま `未同期を送信` を押して、`48枚マスター` に行が追加されるか確認できます。確認後、シート側のテスト行は削除して大丈夫です。

シート側が無反応の時は、`google-apps-script/Code.gs` を貼り直してから、Apps Scriptの `デプロイを管理` -> 対象デプロイの編集 -> `バージョン` で `新バージョン` を選び、再デプロイしてください。保存だけだとWebアプリURLが古いコードのまま動くことがあります。

## 共有URL

公開URLをスタッフへ渡すだけで使えます。Apps Scriptの `/exec` URLと同期署名鍵はサーバー側だけに保持するため、共有先でURLを入力する必要はありません。
